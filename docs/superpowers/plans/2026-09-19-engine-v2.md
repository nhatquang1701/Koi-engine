# Koi Engine v2 plan

Goal: a full-breadth improvement program for the Koi engine and its NNUE
Studio. Build the missing measurement infrastructure (SPRT and a
classical-vs-classical A/B path), make the Studio adopt a freshly trained
network automatically (gate + not-weaker-than-installed), redesign the Studio's
tkinter presentation for responsiveness and theming, then modernize the engine
itself: NNUE hot-path speed, transposition-table indexing, Lazy SMP, the
deferred search-modernization bundle, move generation and legality, and the
evaluation pipelines. No training runs are performed by the agent; the user
trains later through the Studio, and the adoption pipeline is exercised with
the networks that already exist. Commit at every phase boundary and push when
the final suites pass.

## Hard constraints

- Windows x64, MSVC only; builds go through the repository CMake/Ninja trees.
- Classical evaluation remains the engine default; NNUE stays opt-in with the
  safe classical fallback.
- The UCI handshake stays byte-identical unless a phase explicitly adds an
  option; any such addition updates `tests/data/uci/handshake.txt`, the
  controller tests, the process test, and the README option lists together.
- stdout stays protocol clean with exactly one `bestmove` per search.
- Never weaken or delete an assertion to obtain a green run. Pinned search
  expectations (node counts, exact scores, PVs) may change only with recorded
  evidence: SPRT, the 64-position tactical gate, perft, and shadow-diff.
- Elo, CPL, and NPS are reports, never CI thresholds or claims.
- Do not commit `.opencode/`, generated corpora, networks, run directories, or
  other artifacts.
- Commit at every phase boundary with a descriptive imperative message; push
  only at the end of the program (or when a phase explicitly says so).

## Global decisions

- Program breadth: all workstreams, ordered so the Studio/adoption and
  measurement infrastructure land before engine-strength work.
- Studio auto-adopt policy: after a run completes, run the 64-position gate;
  when a network is already installed, additionally run `net_match.ps1` and
  install only when the candidate is not weaker than the installed network
  (skip the comparison when nothing is installed). Versioned backups and a
  one-click revert keep every adoption reversible.
- Running-engine handling: the Studio detects `koi-engine` processes, records
  the adoption in a small registry, and tells the user to restart the engine or
  send `setoption name EvalFile <path>`; no UCI client is added.
- Studio presentation: restyle + responsiveness. Keep the notebook structure;
  add light/dark ttk themes, DPI awareness, scrollable tabs, keyboard
  shortcuts, chart polish, validation progress/cancel, and move blocking work
  off the Tk thread.
- Search-behavior tests may be updated with recorded evidence; the rules
  oracle (perft + shadow-diff) and the 64/64 tactical gate stay mandatory.
- Threading: Lazy SMP for `Threads > 1`; `Threads == 1` stays fully
  deterministic. Threaded parity tests and the release-verify thread
  expectations are relaxed to per-thread determinism, legality, and coverage
  sanity, and the change is documented.
- The NNUE feature-set extension (threat/HalfKA_hm family) is implementation
  only in this program: container scaffolding, encoders, parity tests, and
  trainer configuration. Strength claims wait for the user's training campaign.

## Phase 2 — Studio auto-adopt and engine pickup

- [x] `studio_core`: `run_net_match()` wrapper around `net_match.ps1`;
  `adoption_decision(gate, net_match, installed)` pure policy (install when the

  shows the restart/`EvalFile` notice when an engine process is detected; a
  "Revert last adoption" button; a Runs-tab "Adopt best run" action (sort by

- [x] Tests: policy matrix, registry round-trip and revert, settings

## Phase 4 — NNUE hot-path speed

- [x] Remove the per-make full `EvaluationFeatureExtractor::extract` call from
  `apply_move_deltas`: derive feature deltas from `MoveMetadata` and the child
  position (king square and bucket, moved/captured/placed pieces), apply them
  with a SIMD (AVX2) or vectorized scalar row update, and cache the
  piece-count bucket on the slot. Eliminate the per-make copies of both
  perspective accumulators where the parent slot is already the child's
  parent, and avoid re-encoding sparse features per evaluation.
- [x] Keep the scalar reference path and the existing incremental parity tests;
  add tests that pin the new delta derivation against full recompute over
  scripted castling, en-passant, promotion, and king-crossing games.
- [x] Measure with `koi-bench --timed` and `performance_gate.ps1` against the
  Phase 0 NNUE baseline. Commit.

## Phase 5 — transposition table and per-node cost

- [x] Power-of-two cluster indexing (mask instead of modulo) plus software
  prefetch of the probe cluster; keep the striped-lock and replacement
  semantics and the existing TT tests green.
- [x] Reduce per-node zeroing and copies (move-list initialization, failed-move
  arrays, snapshot history copies) without changing search semantics.
- [x] Node-count tests may move only with recorded evidence (64/64 gate,
  perft/shadow-diff, full suites, NPS report). Commit.

## Phase 6 — Lazy SMP for Threads > 1

- [x] Persistent worker pool with helper threads searching the same tree with
  depth/history jitter, sharing the transposition table and the time budget
  (ordering histories stay worker-local, Stockfish-style, so they need no
  cross-thread synchronization); `Threads == 1` keeps the current
  deterministic serial path unchanged.
- [x] Update the threading tests, the XFAIL/intermittent lists, and
  `release_verify.ps1` thread expectations to per-thread determinism plus
  legality/coverage sanity instead of cross-thread equality; document the
  `Threads > 1` nondeterminism in the README.
- [x] Record SPRT at Threads 4 versus the previous commit and the NPS scaling
  at Threads 1/2/4/8. Commit.

## Phase 7 — search modernization bundle

Each feature is its own commit with its own gate run: static-eval correction
history (pawn/material/king correction tables), true internal iterative
deepening, late-move pruning tables, quiescence TT cutoffs, MultiPV per-line
aspiration windows, and time-manager refinements. Each must pass the 64/64
tactical gate, perft and shadow-diff, the full suites, and a recorded SPRT
against the previous commit; pinned node/score expectations move only with
that evidence.

## Phase 9 — evaluation pipelines (implementation only, no training)

- [ ] Classical: extend the tuner into an adoption workflow: candidate

  Adopt only on a recorded positive result; otherwise keep the canonical
  weights with the evidence.
- [ ] NNUE: scaffold the threat/HalfKA_hm feature family as a new container

- [ ] Full Release and Debug suites at the final HEAD, a `release_verify.ps1`

## Deferred

- Chess960 and other variants, NNUE strength claims or training, ROCm/Metal
  bullet backends, GPU-based search, tablebase probing inside the search,
  opening-book learning, and a full re-tune of every search constant.
