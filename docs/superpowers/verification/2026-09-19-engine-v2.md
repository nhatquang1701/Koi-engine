## Phase 1 — SPRT and classical A/B harness

### Sequential testing in `tools/stability/uci_match.ps1`

- New parameters: `-Sprt`, `-SprtElo0` (default 0), `-SprtElo1` (default 5),
  `-SprtAlpha` (0.05), `-SprtBeta` (0.05), `-SprtMinGames` (20),
  `-SprtMaxGames` (2000). `-Sprt` requires `elo1 > elo0` and
  `max >= min`. The fixed-games `-Games` range was raised from 1..100 to
  1..100000 for long sequential runs.
- `Get-SprtState` computes the normal-approximation LLR from the trinomial
  score: `mu0`/`mu1` are the logistic win rates for the two Elo hypotheses,
  `lower = ln(beta/(1-alpha))`, `upper = ln((1-beta)/alpha)`, and
  `llr = (mu1-mu0)*(2*score - n*(mu0+mu1)) / (2*variance)` with the sample
  variance over `n-1`. A degenerate sample (all wins or all draws) has zero
  sample variance, so the estimator falls back to the null variance
  `mu0*(1-mu0)` instead of a floor; the earlier 1e-6 floor manufactured an LLR
  of -103 from four draws and is gone.
- Game classification for sequential runs: `1-0`/`0-1` score wins/losses from
  Koi's color, `1/2-1/2` and games that run into the ply cap (`*` with
  termination `max plies`) are adjudicated draws, and process failures,
  timeouts, and illegal moves stay outside the score (the match already aborts
  on those).
- The report gains a top-level `sprt` object in the `koi-uci-match-v2` schema:
  `enabled/elo0/elo1/alpha/beta/min_games/max_games/llr/lower/upper/decision/
  games/wins/draws/losses/aborted/elo`; a `running` decision is reported as
  `inconclusive`, and disabled runs report `{enabled:false, decision:'disabled'}`.
  Existing keys are unchanged.

### Fixture and process tests

- `tests/integration/tools/uci_match_fixture.cpp` gained `mate-white`
  (`e2e4 f1c4 d1h5 h5f7`) and `passive-black` (`e7e5 b8c6 g8f6`) scripts plus
  `sprt-alternator-white`/`-black` scripts that alternate a mating line and a
  passive line by game parity. `ucinewgame` now resets the per-game move
  counter, which the previous fixture did not do and which broke multi-game
  runs.
- `tests/integration/matches/uci_match_process_test.ps1` runs three sequential
  cases: a forced winner accepts at the first legal stop, a forced loser
  rejects, and the alternator runs to the cap and reports `inconclusive` with
  an LLR near zero. The forced cases use `-SprtElo1 200` because a 100% score
  against `elo1 = 5` only gains about 0.014 LLR per game, which is correct
  SPRT behaviour but cannot stop inside a 100-game cap.
- `ctest --test-dir build/release -R koi_uci_match_process` passes in 23.17 s,
  including the three new cases.

### Classical candidate-vs-baseline workflow

- The baseline engine binary was copied to
  `artifacts/verification/engine-v2/baseline-engine/` (engine plus
  `koi-replay.exe`), and the current Release build played it through
  `uci_match.ps1 -Sprt` at depth 3, 8-game cap, 30-ply cap, 30 s per move:
  all eight games were adjudicated draws, `llr = -0.000828`,
  `decision = inconclusive`, `aborted = 0`
  (`artifacts/verification/engine-v2/classical-sprt-5/`, log
  `classical-sprt-5.out.log`). Identical binaries therefore stay inconclusive
  exactly as expected, and the report is recorded as the workflow baseline for
  later parameter campaigns.
- A first attempt at the workflow exposed the two defects fixed above: the
  match script originally counted ply-capped games as aborted, and the variance
  floor produced a false `reject` from four draws. Both are covered by the
  process tests and the rerun evidence.

## Phase 2 — Studio auto-adopt and engine pickup

### Core adoption layer (`tools/nnue/studio_core.py`)

- Settings live in `artifacts/studio/settings.json` (schema
  `koi-studio-settings-v1`): `engine_directory`, `auto_adopt`, `theme`,
  `geometry`, `ab_games`, `ab_nodes`, `gate_games`, `net_match_nodes`.
  `read_settings` merges over `default_settings()` and ignores malformed files;
  `write_settings` rewrites the merged payload with the schema marker.
- `run_net_match`/`net_match_command` wrap `tools/nnue/net_match.ps1`
  (candidate vs installed network, `-NnueNet/-OpponentNet/-Games/-Nodes/
  -Threads/-ReportPath`) and parse the `koi-nnue-net-match-v1` report the same
  way `run_ab_match` parses the A/B report.
- `adoption_decision(gate, net_match, installed)` returns `adopt` or `skip`
  plus a reason. `adopt` requires a gate that ran without `error`/`rejected`
  and with `positions > 0`; when a network is already installed the comparison
  must report `candidate-stronger` or `inconclusive` — `candidate-weaker`,
  a missing comparison, or an unknown verdict all skip. With nothing installed
  the comparison is skipped by design.
- `adopt_net` installs through `install_net` (timestamped `.bak` of the
  previous `koi.nnue`) and appends a record to
  `artifacts/studio/adoptions.json` (schema
  `koi-nnue-adoption-registry-v1`): `installed_utc`, `source_run`,
  `source_net`, `installed_path`, `backup_path`, `bytes`, `gate`,
  `ab_verdict`, `net_match_verdict`, `reverted_utc`.
  `revert_adoption` restores the newest non-reverted backup over the installed
  file (first saving the current file as `*.revert.bak`) and marks the record
  reverted.
- `running_engines()` lists `koi-engine` PIDs through `tasklist`; the Studio
  uses it to warn that a running engine keeps its loaded evaluator until it is
  restarted or receives `setoption name EvalFile`.

### GUI wiring (`tools/nnue/koi_nnue_studio.py`)

- An "Auto-adopt" checkbox sits next to "Validate when finished"; both the
  engine directory and the checkbox are restored from settings at startup and
  persisted on install/adopt and on window close (`_save_settings`), together
  with the remembered geometry and A/B values.
- After a finished run, the existing auto-validation path runs the gate and
  A/B match as before; when Auto-adopt is enabled the validation worker then
  compares the candidate with the installed network (skipped when none is
  installed or the candidate *is* the installed file), applies
  `adoption_decision`, and on `adopt` installs and records the adoption — all
  off the Tk thread.
- The validation pane prints the decision, the net-match line, the installed
  path, the backup path, and the restart/`EvalFile` notice when engine
  processes were found. A skipped decision leaves the manual install button
  available whenever the gate passed.
- The Runs tab gained "Adopt best run": it picks the completed run with the
  lowest validation MAE and runs the same gate/compare/adopt pipeline.

## Limitations

- No training runs are performed in this program; NNUE strength statements
  wait for the user's campaign through the Studio.
- Elo/SPRT outputs are local reports, not claims; hardware and time controls
  are recorded with every report.
- Lazy SMP makes `Threads > 1` nondeterministic by design; only `Threads == 1`
  keeps the exact deterministic guarantee.
