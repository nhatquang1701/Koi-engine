## Phase 1 — SPRT and classical A/B harness

### Sequential testing in `tools/stability/uci_match.ps1`

- New parameters: `-Sprt`, `-SprtElo0` (default 0), `-SprtElo1` (default 5),
  `-SprtAlpha` (0.05), `-SprtBeta` (0.05), `-SprtMinGames` (20),
  `-SprtMaxGames` (2000). `-Sprt` requires `elo1 > elo0` and
  `max >= min`. The fixed-games `-Games` range was raised from 1..100 to
  1..100000 for long sequential runs.
- `Get-SprtState` computes the normal-approximation LLR from the trinomial
  score: `mu0`/`mu1` are the logistic win rates for the two Elo hypotheses,
  `lower = ln(beta/(1-alpha))`, `upper = ln((1-beta)/alpha)`, and
  `llr = (mu1-mu0)*(2*score - n*(mu0+mu1)) / (2*variance)` with the sample
  variance over `n-1`. A degenerate sample (all wins or all draws) has zero
  sample variance, so the estimator falls back to the null variance
  `mu0*(1-mu0)` instead of a floor; the earlier 1e-6 floor manufactured an LLR
  of -103 from four draws and is gone.
- Game classification for sequential runs: `1-0`/`0-1` score wins/losses from
  Koi's color, `1/2-1/2` and games that run into the ply cap (`*` with
  termination `max plies`) are adjudicated draws, and process failures,
  timeouts, and illegal moves stay outside the score (the match already aborts
  on those).
- The report gains a top-level `sprt` object in the `koi-uci-match-v2` schema:
  `enabled/elo0/elo1/alpha/beta/min_games/max_games/llr/lower/upper/decision/
  games/wins/draws/losses/aborted/elo`; a `running` decision is reported as
  `inconclusive`, and disabled runs report `{enabled:false, decision:'disabled'}`.
  Existing keys are unchanged.

### Fixture and process tests

- `tests/integration/tools/uci_match_fixture.cpp` gained `mate-white`
  (`e2e4 f1c4 d1h5 h5f7`) and `passive-black` (`e7e5 b8c6 g8f6`) scripts plus
  `sprt-alternator-white`/`-black` scripts that alternate a mating line and a
  passive line by game parity. `ucinewgame` now resets the per-game move
  counter, which the previous fixture did not do and which broke multi-game
  runs.
- `tests/integration/matches/uci_match_process_test.ps1` runs three sequential
  cases: a forced winner accepts at the first legal stop, a forced loser
  rejects, and the alternator runs to the cap and reports `inconclusive` with
  an LLR near zero. The forced cases use `-SprtElo1 200` because a 100% score
  against `elo1 = 5` only gains about 0.014 LLR per game, which is correct
  SPRT behaviour but cannot stop inside a 100-game cap.
- `ctest --test-dir build/release -R koi_uci_match_process` passes in 23.17 s,
  including the three new cases.

### Classical candidate-vs-baseline workflow

- The baseline engine binary was copied to
  `artifacts/verification/engine-v2/baseline-engine/` (engine plus
  `koi-replay.exe`), and the current Release build played it through
  `uci_match.ps1 -Sprt` at depth 3, 8-game cap, 30-ply cap, 30 s per move:

## Phase 2 — Studio auto-adopt and engine pickup

### Core adoption layer (`tools/nnue/studio_core.py`)

- Settings live in `artifacts/studio/settings.json` (schema
  `koi-studio-settings-v1`): `engine_directory`, `auto_adopt`, `theme`,
  `geometry`, `ab_games`, `ab_nodes`, `gate_games`, `net_match_nodes`.
  `read_settings` merges over `default_settings()` and ignores malformed files;
  `write_settings` rewrites the merged payload with the schema marker.
- `run_net_match`/`net_match_command` wrap `tools/nnue/net_match.ps1`
  (candidate vs installed network, `-NnueNet/-OpponentNet/-Games/-Nodes/
  -Threads/-ReportPath`) and parse the `koi-nnue-net-match-v1` report the same
  way `run_ab_match` parses the A/B report.
- `adoption_decision(gate, net_match, installed)` returns `adopt` or `skip`
  plus a reason. `adopt` requires a gate that ran without `error`/`rejected`
  and with `positions > 0`; when a network is already installed the comparison
  must report `candidate-stronger` or `inconclusive` — `candidate-weaker`,
  a missing comparison, or an unknown verdict all skip. With nothing installed
  the comparison is skipped by design.
- `adopt_net` installs through `install_net` (timestamped `.bak` of the
  previous `koi.nnue`) and appends a record to
  `artifacts/studio/adoptions.json` (schema
  `koi-nnue-adoption-registry-v1`): `installed_utc`, `source_run`,
  `source_net`, `installed_path`, `backup_path`, `bytes`, `gate`,
  `ab_verdict`, `net_match_verdict`, `reverted_utc`.
  `revert_adoption` restores the newest non-reverted backup over the installed
  file (first saving the current file as `*.revert.bak`) and marks the record
  reverted.
- `running_engines()` lists `koi-engine` PIDs through `tasklist`; the Studio
  uses it to warn that a running engine keeps its loaded evaluator until it is
  restarted or receives `setoption name EvalFile`.

### GUI wiring (`tools/nnue/koi_nnue_studio.py`)

- An "Auto-adopt" checkbox sits next to "Validate when finished"; both the
  engine directory and the checkbox are restored from settings at startup and
  persisted on install/adopt and on window close (`_save_settings`), together
  with the remembered geometry and A/B values.
- After a finished run, the existing auto-validation path runs the gate and
  A/B match as before; when Auto-adopt is enabled the validation worker then
  compares the candidate with the installed network (skipped when none is
  installed or the candidate *is* the installed file), applies
  `adoption_decision`, and on `adopt` installs and records the adoption — all
  off the Tk thread.
- The validation pane prints the decision, the net-match line, the installed
  path, the backup path, and the restart/`EvalFile` notice when engine
  processes were found. A skipped decision leaves the manual install button
  available whenever the gate passed.
- The Runs tab gained "Adopt best run": it picks the completed run with the
  lowest validation MAE and runs the same gate/compare/adopt pipeline.

## Phase 4 — NNUE hot-path speed

Changed surface: `src/koi/nnue.cpp`, `src/koi/nnue.hpp`,
`src/koi/evaluation_features.hpp`, `src/koi/evaluation_features.cpp`, and
`tests/unit/evaluation/nnue_boundary_tests.cpp`.

### Incremental make path

- `NnueWorker::apply_move_deltas` no longer extracts the child feature view on
  the hot path. Every delta is derived from `MoveMetadata` plus the child's side
  to move; the only remaining `EvaluationFeatureExtractor::extract(child)` runs
  when a perspective's own king crosses a king-bucket boundary. That decision
  uses the new `EvaluationFeatureExtractor::halfka_king_bucket_for_square(to,
  real)` compared against the slot's cached bucket, so a king step inside one
  bucket is now a plain remove/add pair and only a genuine crossing (including
  every castle, which always crosses) rebuilds the perspective.
- `apply_feature_delta` gained an AVX2 path (`apply_delta_avx2`): 8 int32 lanes
  per iteration with `_mm256_cvtepi16_epi32`, per-block overflow detection
  (same-sign operands with a changed result sign) that redoes the overflowing
  block through the scalar int64-accumulate/int32-clamp loop, and a scalar tail.
  The scalar loop stays the reference and runs whenever AVX2 is unavailable or
  the width is not a multiple of 8.
- `NnueWorker` caches the piece count per slot (`slot_pieces_`) and in the
  scratch view (`scratch_pieces_`). `evaluate(const GameState&)` therefore picks
  the output bucket with `output_bucket_for_pieces(...)` without rescanning the
  board and without materializing `EvaluationFeatures`; only the full-rebuild
  branch extracts features. `piece_count_bucket(features)` was split into
  `piece_count_of` and `output_bucket_for_pieces`.
- Bug found and fixed during the pass: the first AVX2 delta implementation
  loaded 16 int32 lanes but converted only 8 int16 weights per iteration, which
  silently left the upper half of each block un-updated. The incremental parity
  tests caught it (three failing cases) and the loop was corrected to 8 lanes
  per iteration before the phase was recorded.

### Tests

- `nnue_boundary_tests` now has 28 cases: 27 pass and 1 environment skip
  (external container) in both Release and Debug.
- New `NNUE v4 incremental wide deltas` plays a scripted game on saturating
  biases (`INT32_MAX - 100`) with alternating `32767` / `-32768` feature rows so
  the AVX2 delta path must take its overflow fallback and still match a full
  recompute.
- The existing incremental walk, king-bucket crossing, scripted special-move,
  and skipped-hook recovery parity tests are unchanged and green.

## Phase 5 — transposition table and per-node cost

Changed surface: `src/koi/transposition_table.hpp`,
`src/koi/transposition_table.cpp`, `src/koi/detail/search_table_access.hpp`,
`src/koi/detail/search_context.cpp`, `src/koi/game_state.hpp`,
`src/koi/game_state.cpp`, `src/koi/detail/search_context.hpp`,
`src/koi/detail/search_runner.cpp`, `tests/unit/core/koi_core_tests.cpp`, and
`tests/unit/runtime/transposition_table_tests.cpp`.

### Power-of-two cluster indexing

- `Storage` rounds the cluster count down to a power of two
  (`round_down_power_of_two`) and keeps `cluster_mask = cluster_count - 1`.
  `store`/`probe` index with `key & cluster_mask` instead of `key % cluster_count`,
  and the stripe is `cluster & (kStripeCount - 1)` (the count is already a power
  of two; a `static_assert` pins that).
- `entries_per_segment` is also a power of two with a shift/mask pair in
  `Storage::at`, so the four-entry cluster lookup no longer divides per entry.
  Clusters never straddle segments because both the segment size and the cluster
  count are multiples of `kClusterSize`.
- `rounded_size_mb()` computes the same allocation the constructor will make, so
  `resize_locked` compares and reports the rounded size instead of re-allocating
  on every odd request. A power-of-two `Hash` (the UCI default 512, and the 1/2/4
  MB sizes the tests use) is unchanged; a request like 3 MB reports 2 MB.
- Replacement, generation ageing, Clear Hash, and `hashfull` semantics are
  untouched; only the index arithmetic changed.

### Probe prefetch

- `TranspositionTable::prefetch(key)` issues `_mm_prefetch(..., _MM_HINT_T0)` on
  the cluster's first entry under MSVC x86/x64, `__builtin_prefetch` under
  GCC/Clang, and a no-op elsewhere. `probe()` prefetches before taking the
  stripe lock so callers that prefetch earlier already have the fetch in flight.
- `detail::SearchTableAccess::prefetch` forwards the call and stays a complete
  no-op for a disabled view. `SearchContext::negamax` now computes the node's
  `transposition_key` once, right after `record_ply`, prefetches there, and
  reuses the same key for the probe and the store (it was previously computed
  three times per node).

### Per-node zeroing and copies

- `MoveMetadata` no longer carries default member initializers beyond `Move`'s
  own sentinel, and `MoveMetadataList` leaves its 256-entry storage
  uninitialized (only `[0, size())` is ever read). That removes roughly 10 KiB of
  stores per negamax and per qsearch node. The list declares copy/move
  operations that copy only the live prefix, because an implicit array copy
  would read the uninitialized tail (`moves = *root_moves` and the several
  `MoveMetadataList x = y;` root paths now copy `size()` entries).
- The four sites that need a zeroed record say so explicitly:
  `GameState::describe_move`, `DeferredHistoryMove::metadata()`, the two root
  fallback candidate structs in `search_runner.cpp`, and the fabricated-metadata
  core test.
- `legal_moves_with_metadata` and `legal_tactical_moves_with_metadata` no longer
  value-initialize their 256-entry `std::array<Move, ...>` scratch buffer; the
  generator writes every entry that is later read.
- The `failed_moves` array was already intentionally uninitialized and the
  en-passant snapshot copy was already replaced by an in-place probe in an
  earlier pass, so no further change was needed there.

## Phase 6 — Lazy SMP

### Implementation

`Threads > 1` now starts `Threads - 1` helper threads that run the same
iterative deepening as the main thread while sharing the transposition table,
the time budget, and the root position. The main thread keeps the serial
driver: it owns root-move generation, aspiration, result publication, and stop
signaling, and it is the only thread that publishes `info`/`bestmove`. Helpers
never publish.

- `detail::LazySmpPool` (`src/koi/detail/search_runner.cpp`, immediately before
  `RootWorkerPool`) owns a copy of the root `GameState`, one `SearchContext`
  per helper, and a per-helper `SearchStats` slot. Each helper runs
  `begin_iteration` + `negamax` from depth `1 + index % 3`, accumulates its own
  stats, and increments depth until it is told to stop.
- Helpers are stopped through two `std::atomic_bool` flags (`stopping_` and
  `helper_abort_`) that are also observed by `SearchContext::interrupted()`.
  `SearchContext::begin_iteration` installs the shared abort pointer without
  clearing it, so a helper that was aborted stays aborted.
- The pool is started before the dispatch chain when
  `threads > 1 && multi_pv == 1 && no node limit && !short_tactical_budget &&
  !claimable_draw && !forced_draw && at least two legal root moves`, and
  `use_lazy_smp` routes that search through the serial (main-thread) driver.
  After the chain the pool is stopped and its stats are merged into
  `result.stats`; helper nodes therefore show up in the reported node counts
  without changing result selection.
- `Threads == 1` keeps the pre-existing serial path byte-for-byte. The
  root-parallel path is retained for `MultiPV > 1`, node-limited searches,
  forced/claimable draws, and short tactical budgets.
- Ordering histories (killers, counter moves, continuation/pawn history) stay
  worker-local rather than shared: Stockfish-style Lazy SMP shares the
  transposition table and the time budget, and keeping the histories
  per-thread avoids turning every history update into an atomic operation.
  The shared-state surface is therefore the TT plus the stop flags.

### Test and harness policy

- All four `koi_search_tests` shards pass with 0 failures and 0 XPASS; the 16
  `known_failures` entries still fail exactly as before, so no list changes
  were needed.
- `tools/build/release_verify.ps1` now scopes the repeat-identity assertion to
  `Threads = 1` (with a comment explaining the guarantee) and adds a
  repeat-coverage equality check for every thread count. The summary line reads
  `repeat=identical` for Threads 1 and `repeat=lazy-smp` for the rest; row
  structure, coverage, and legal-move checks stay in force for all counts, and
  the timed run is strict only at Threads 1.
- `README.md` documents `Threads = 1` as the deterministic serial search and
  `Threads > 1` as Lazy SMP (nondeterministic, validated for legality and
  coverage rather than byte equality); the architecture note records that
  Lazy SMP has landed and only shared histories remain future work.
  `tests/README.md` gained the matching determinism bullet.

## Phase 7 — search modernization bundle

### Feature 1 — bounded static-eval correction history

The first bundle feature adds Stockfish-style correction history without touching
any score that reaches the transposition table.

- `SearchOrderingTables` owns three worker-local correction tables keyed by
  structural fingerprints: `kPawnCorrectionHistorySize = 16 * 1024`,
  `kMaterialCorrectionHistorySize = 8 * 1024`, and
  `kKingCorrectionHistorySize = 8 * 1024`, each entry capped at
  `kCorrectionEntryLimit = 128` and the summed correction capped at
  `kCorrectionTotalLimit = 192`.
- `SearchContext::correction_keys_for(state)` derives the keys cheaply:
  `state.pawn_key()` for the pawn key, an FNV-1a fold over the ten
  `popcount(piece_bitboard(type, color))` counts for pawn..queen as the material
  signature, and `countr_zero(piece_bitboard(king, side_to_move))` as the king
  key (64 when no king is present). This uses the new
  `GameState::piece_bitboard(PieceType, Color)` forwarder, so no feature
  snapshot is rebuilt.
- The raw evaluator score at the negamax node is corrected with
  `static_eval = raw_eval + ordering.correction_value(keys...)` before it is
  stored in the frame, so `improving`, `opponent_worsening`, razoring, null
  move, reverse futility, ProbCut, and the futility gates all see the corrected
  value, while TT stores keep the search score unchanged.
- After the search score is final (and after the TT-floor adjustment, before the
  store) the history is fed with
  `bonus = clamp((best_score - static_eval) * min(depth, 8) / 8, ±48)`, gated on
  `correction_keys_valid && !claimable_draw && best_metadata_valid &&
  std::abs(best_score) < kMateThreshold`; each non-zero bonus saturates the
  three tables and increments the new
  `SearchStats::correction_history_updates` counter.
- Quiescence stand-pat evaluation is deliberately left raw in this feature so
  the change stays confined to the main search; that is recorded as deferred.

Tests added: `tests/unit/search/search_ordering_tests.cpp` gained
`correction history saturation` (starts neutral, saturates at the entry and
total limits in both directions, `clear()` resets) and
`tests/unit/search/koi_search_tests.cpp` gained
`static eval correction history` (a depth-5 startpos search reports
`correction_history_updates > 0`).

### Threaded test re-scoping (evidence correction)

The Phase 6 shard and CTest rows in this record were produced against a
`koi_search_tests.exe` that predated the Lazy SMP dispatch change: a stash
experiment (`git stash` of the Phase 7 work, rebuild, focused runs) showed the
same four tests failing at the Phase 6 commit, so the earlier "green" rows were
stale rather than the Phase 7 feature breaking them. The four obsolete
assertions were re-scoped to thread-count-independent invariants under the
Phase 6 policy:

- `short timed multithread overlap` (was `short timed root workers`) asserts
  overlapping evaluations through `ConcurrencyEvaluator::maximum_active()`.
- `threaded single-PV evaluates the root iteration` (was
  `threaded single-PV root is authoritative`) asserts a legal root move, the
  completed depth, and a lower bound on evaluations instead of the exact
  scheduling-dependent count.
- `threaded single-PV uses lazy smp` (was `threaded root alpha sharing`) asserts
  the same overlap plus `result.stats.root_pvs_searches == 0`, pinning that a
  plain `Threads > 1` search leaves the root pool unused.
- `threaded cancellation` relaxes its evaluation count to a lower bound for the
  same reason.
