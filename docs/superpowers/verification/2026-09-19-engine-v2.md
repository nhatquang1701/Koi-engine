# Koi Engine v2 verification

Record for the program planned in
`docs/superpowers/plans/2026-09-19-engine-v2.md` with the contracts in
`docs/superpowers/specs/2026-09-19-engine-v2-design.md`.

## Environment

- Windows x64, MSVC (VS Community 2022 toolchain, Ninja generators), C++26.
- Python 3.14.5, python-chess 1.11.2, numpy, torch 2.14.0+cpu.
- CUDA 12.9.1, cargo 1.98.1, GTX 1060 6GB (`sm_61`), 8 logical CPUs.
- Repository baseline HEAD `f8b49ad` on branch `koi-engine-v1`, in sync with
  origin at program start.

## Phase 0 — baseline and documentation

- Scaffolding committed: this record, the plan, the design spec, and one index
  row in each of the three `docs/superpowers/` README tables.
- Baseline commands (logs under `artifacts/verification/engine-v2/`):
  - `ctest --test-dir build/release -j 4 --output-on-failure`
  - `ctest --test-dir build/debug -LE heavy -j 4 --output-on-failure`
  - `build\release\koi-bench.exe --threads 1 --timed`
  - `build\release\koi-bench.exe --nnue artifacts\training\koi-v4-1024.nnue --threads 1 --timed`
- Results (wrapper `koi-engine-v2-baseline.cmd`, `baseline-exits.txt` =
  `RELEASE_EXIT=0`, `DEBUG_EXIT=0`, `BENCH_CLASSICAL_EXIT=0`,
  `BENCH_NNUE_EXIT=0`):
  - Release CTest: 100% passed, 0 failed out of 59 (`baseline-ctest-release.log`).
  - Debug non-heavy CTest: 100% passed, 0 failed out of 51
    (`baseline-ctest-debug.log`).
  - Classical bench (`--threads 1 --timed`, 64 positions): 64/64 expected moves,
    754,289 nodes + qnodes in 6,031 ms = **125,069 nps**
    (`baseline-bench-classical.log`).
  - NNUE bench (`--nnue artifacts\training\koi-v4-1024.nnue`, same flags):
    61/64 expected moves, 488,368 nodes + qnodes in 6,775 ms = **72,084 nps**
    (`baseline-bench-nnue.log`).
  - The NNUE aggregate is ~57% of the classical throughput on this host, which
    is the target for the Phase 4 hot-path work; the absolute figures are host
    measurements, not thresholds.

## Limitations

- No training runs are performed in this program; NNUE strength statements
  wait for the user's campaign through the Studio.
- Elo/SPRT outputs are local reports, not claims; hardware and time controls
  are recorded with every report.
- Lazy SMP makes `Threads > 1` nondeterministic by design; only `Threads == 1`
  keeps the exact deterministic guarantee.
