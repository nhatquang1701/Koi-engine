# Koi Engine 1.1.0

Koi Engine 1.1.0 refines search quality and makes long analyses feel live in
GUI frontends, alongside internal test and tooling hardening.

## Highlights

### Search quality

- **Transposition-table key reuse**: the stored key no longer carries the
  repetition fingerprint, so equivalent positions share table entries more
  often. The fixed-depth probe measured about 21% fewer nodes with a
  no-regression self-play gate.
- **Bounded singular-extension ladder**: singular extensions are now budgeted
  per search path. The probe output is byte-identical; this is a principled
  safety bound.
- **Bounded checked-qsearch tail**: the all-evasions full-window tail in
  quiescence is limited to 16 plies (previously 24). The fixed-depth probe
  shows a shallower reported seldepth with no tactical regressions.

### Analysis experience

- **In-flight depth**: during a long iteration the engine now publishes the
  depth being searched with refreshed node, speed, and time values, so a GUI
  readout no longer freezes on the last completed depth.
- **Score provenance**: an iteration whose root verification stayed selective
  republishes the most recent proven score at the current depth; before any
  proven iteration exists, the line omits the score entirely. GUIs never
  receive an unproven score.
- **In-flight principal variation**: interim progress lines stream the current
  root line's principal variation at the interim cadence, so analysis panels
  update continuously instead of jumping once per completed iteration.

### Evaluation

- The classical evaluator remains the default.
- The Koi-native NNUE evaluator (halfka-king-bucket v4 format) can be loaded
  through the `EvalFile` option; the CPU and optional CUDA GPU paths are
  unchanged.
- Evaluation-speed experiments (an arm64 NEON inference path and a
  direct-to-slot accumulator refresh) were measured on the development
  harness and did not meet the shipping bar; neither is included.

## Platforms

- Windows x64 with MSVC (the primary development platform).
- Linux x86-64 with GCC 14+ or Clang 18+.
- macOS arm64 (Apple Silicon) with AppleClang 18+ or Homebrew LLVM.

## Compatibility

- UCI options and defaults are unchanged: `Hash=512`, `Threads=1`,
  `Speed=100`, `OwnBook=false`.
- `EvalFile`, Syzygy tablebases, and Polyglot books remain optional
  user-provided assets. No book, network, or tablebase data ships with the
  engine.
- `Threads=1` remains deterministic; `Threads>1` uses Lazy SMP and is
  intentionally nondeterministic.

## Verification

- Every behavior change carries focused unit coverage plus the full local
  suite on macOS arm64, and the four CI lanes (Linux, macOS, Windows, docs).
- Release packages keep the repository README, the MIT license, the required
  third-party licenses, the package manifest, and a `.sha256` sidecar.
