# Koi Engine 1.1.2 release notes

## Highlights

- **Transposition table efficiency.** The transposition entry is packed from
  32 to 24 bytes, fitting ~33% more entries in the same hash budget; measured
  tree-identical with −2.5% time at equal nodes and neutral in self-play over
  198 games.
- **Slider attacks (x86-64).** Rook, bishop, and queen attacks use PEXT
  bitboard tables on BMI2-capable x86-64 CPUs (the full-engine depth-6 probe:
  tree-identical, +16–23% faster per node). `KOI_PEXT_ATTACKS=OFF` keeps the
  portable ray fallback, exercised in CI.
- **Performance-core preference.** Search worker threads request
  performance-class scheduling: macOS QoS `USER_INITIATED`, Windows
  `THREAD_PRIORITY_ABOVE_NORMAL`, Linux nice −5 (best-effort, fails
  gracefully).
- **Analysis UX (MultiPV speed).** The MultiPV root-parallel path (`Threads>1`
  with `MultiPV>1`) now uses per-move aspiration windows: the Threads=4,
  MultiPV=3 depth-8 probe completes with ~12% fewer nodes and ~7% less time
  (the rank-1 score is unchanged).

## Compatibility

- UCI options, defaults, and the optional-asset behavior are unchanged from
  1.1.1 (`Hash=512`, `Threads=1`, `OwnBook=false`, `EvalFile` optional).
- `Threads=1` remains deterministic; `Threads>1` results are intentionally
  nondeterministic.
- No book, tablebase, or network data ships with the engine.

## Verification

- Full CTest suites on Linux, Windows, and macOS CI; the Mac release
  verification harness (Debug + Release builds, UCI smoke, replay, threading
  and timing checks); self-play A/B runs for each search change.
- Measurement provenance: classical evaluator, Apple M4, the depth-6 probe
  corpus; the ledger records the full profile.
