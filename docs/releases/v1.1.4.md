# Koi Engine v1.1.4

## Highlights

- **Bundled opening book.** Releases now carry a Polyglot opening book generated
  from Lichess's open-source opening data
  ([lichess-org/chess-openings](https://github.com/lichess-org/chess-openings),
  CC0 1.0): `book/koi.bin` in the package, with a `book/COPYING.txt` notice and
  a SHA-256 sidecar. Copy it beside the engine binary as `book.bin` and it is
  detected automatically (`info string book detected: …`); `OwnBook=false`
  disables it, `BookFile` points at a different book, and `BookDepth`,
  `BookRandom`, and `BookSafety` tune how it is used. The book is optional and
  never required to run the engine.
- **Sudden-death time management.** A 5+0 clock no longer gets spent in the
  first moves: the time manager now plans over a 50-ply horizon with a 2x hard
  cap and tapers the hard-position extension at low clock instead of ignoring
  it. In the 5+0 replay simulation the engine keeps 117.5 s of a 300 s clock
  after 40 moves (mean 4.56 s/move).
- **Version 8 network container.** The loader, serializer, and trainer accept
  the version 8 container in the halfka-only layout (the same 9216-input payload
  and math as the version 4 container, different version word), `--arch v8`
  trains it, `nnue-info` inspects any Koi NNUE container, and a version 8
  network is evaluated instead of silently falling back to the classical
  evaluator. The shipped network
  (`koi-v8-512-20261024.nnue`, sha256 `3e75e6d8…5829da`) is a strength-neutral
  container swap: 49.25% against the 1.1.3 network at equal nodes (200 games)
  and 58.59% (+60.3 Elo) against the classical evaluator at equal time (64
  games, 1+0).
- **Lichess bot hardening.** launchd is the single owner of the bot lifecycle,
  orphaned engine workers are cleaned up, and the bot log rotates instead of
  growing without bound. A control script (`tools/bot/koi-bot.sh`) and its guide
  document start/stop/status/update and the launchd install.
- **UCI and search polish.** Interim `info` lines report the in-flight root move
  on a correctly one-based `currmovenumber`, the transcript tests accept the new
  grammar, and an empty-PV guard fixes an AddressSanitizer failure in interim
  move publication.

## Compatibility

- UCI options are unchanged from 1.1.3. `EvalFile` stays optional; an empty
  value keeps the boot-time evaluator, and a rejected network still falls back
  to the classical evaluator.
- GPU NNUE is unchanged: the CUDA path serves version 5 networks only and stays
  unavailable on macOS; the CPU NNUE and classical evaluator paths remain the
  default and the fallback.
- `Threads=1` remains deterministic. `Threads>1` uses Lazy SMP over the shared
  transposition table and is intentionally nondeterministic.
- Release archives carry the CC0 book under `book/`; copy `book/koi.bin` beside
  the binary as `book.bin` to enable automatic book detection. No tablebase data
  is bundled, and the engine works without either optional asset.

## Verification

- Full CI matrix green on the release commit (Windows, Linux, macOS CTest, and
  the documentation build).
- Release-net rule: the shipped network is never weaker than the classical
  evaluator at equal time; the timed gate above is the evidence, recorded with
  the network SHA-256, executable, options, openings, and time control.
- The book is generated from CC0 1.0 source; the package records the generator
  name, source URL, and book SHA-256 in `book/COPYING.txt`.
